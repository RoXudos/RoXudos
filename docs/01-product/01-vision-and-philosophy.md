# Vision and philosophy

## Vision

Event teams can plan, control, run, and review any live event from one operational picture — from a community street party to a festival, Pride parade, or charity mass-participation event.

## Philosophy

1. **Live control is the product.** Everything else exists to make live control true.
2. **Speed under pressure beats completeness in a form.** A control operator must log in seconds.
3. **Simple screens, serious data.** Do not dress operational software like a marketing site.
4. **Humans decide emergencies.** Software shows the procedure and the contacts. It does not call the evacuation.
5. **History is evidence.** Timestamp everything that matters. Do not rewrite it.
6. **Permissions are a safety feature.** Medical, safeguarding, and some security records are not “nice extras”.
7. **Generic core, typed extras.** One platform. Event type only reveals the modules that event needs.
8. **Desktop first, field later.** Build the control room properly before a phone app.
9. **Would this help someone running a live event?** If no, it waits.

## The operational loop

```text
See → Decide → Assign → Act → Record → Review
```

Every primary screen should make one of those steps faster.

## Tone of the product

Professional, modern, fast, operational, calm, clear, reliable.

The UI should feel like a well-run control room, not a startup landing page and not a 2005 government portal.
