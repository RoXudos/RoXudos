# Roadmap phases

Phases are product phases, not calendar estimates.

## Phase A — First production release

See [06-first-production-release.md](06-first-production-release.md).

A real event can be run from a desktop control room.

## Phase B — Field mobile

PWA or native wrapper with large buttons:

- Report incident
- Report issue
- Message control
- View tasks
- View briefing
- Check in / out
- View map
- Request help

Same APIs and RBAC. No second permission model.

## Phase C — Offline and poor connectivity

- Offline incident and log drafts
- Local queue
- Sync with conflict rules
- Cached map and briefing
- Honest sync state

## Phase D — Event-type depth

- Pride / parade live route and group order
- Charity fundraising, sponsors, participants, Gift Aid support
- Artist management
- Logistics and vehicle slots
- Volunteer applications
- Structured plans (not only file attachments)

## Phase E — Intelligence and handover

- Authorised AI assistant
- Facts vs suggestions, labelled
- Handover narrative
- “What is happening at Gate 2?”
- Still no emergency autonomy

## Phase F — Network effects and public

- Public emergency notifications if legally designed
- Limited emergency-service view
- Multi-region data residency (US region option)
- Self-serve billing

## Explicit non-goals for a long time

- Becoming a ticket marketplace
- Replacing radio hardware
- Storing CCTV video
- Acting as an NHS or US medical record
- Social network for attendees
