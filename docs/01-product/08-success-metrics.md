# Success metrics

Vanity sign-ups do not matter if control still runs on WhatsApp.

## Product metrics that matter

| Metric | Why |
| --- | --- |
| Time to create a control-log line | Must be seconds, not a form expedition |
| Time to create an incident from a blank dashboard | Same |
| Share of incidents with a location and assignee | Incomplete records are how control fails |
| Open critical incidents older than an agreed threshold | Stale criticals are a process smell |
| Handover report generated and opened at shift change | Proves the live picture is trusted |
| Percentage of staff checked in during a live event | Proves people module is used |
| Audit completeness on closed incidents | Evidence quality |
| WhatsApp / paper still used for the same job | Qualitative. Ask after the event. |

## First-event success

The first real event is a success if:

1. Event control used Livehelm as the live picture for the whole operational period.
2. Incidents and the control log were not reconstructed afterwards from paper.
3. The post-event report was generated from the system, then edited, not written from scratch.
4. No cross-tenant or sensitive-module leak occurred.
5. The next event can be cloned.

## Business metrics come after that

- Organisations that run a second event on the platform
- Paid organisations
- Time-to-value: first incident logged after signup

Do not add a growth dashboard before the control room is trusted.
