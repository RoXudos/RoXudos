# Event lifecycle

```text
PLAN → BUILD → BRIEF → OPERATE → RESPOND → CLOSE → REVIEW
```

The product follows the event, not the other way around.

## PLAN

Create the event, set type, dates, venue, expected attendance, departments, and which modules are on.

Write or attach plans: event management, emergency, security, medical, fire, traffic, crowd, accessibility, communications, weather, evacuation.

Clone last year’s event if it exists, then change what changed.

## BUILD

Site map, zones, locations, vendors, contractors, deliveries, accreditation rules, staff roles, rotas.

Build and derig dates are first-class, not a footnote.

## BRIEF

People get the briefing for their role and location. Training flags and document checks sit here.

A person should not have to hunt through five PDFs to know their post and radio channel.

## OPERATE

The live control room.

Attendance, staff on site, programme now/next/later, map, tasks, weather, department status, control log.

This is the default screen while the event is `live`.

## RESPOND

Incidents, dispatch, emergency playbooks, alerts, restricted medical and safeguarding flows.

Humans decide. The system timestamps, assigns, and shows the procedure.

## CLOSE

Event status moves to `closed`. Open incidents and tasks are either closed or explicitly carried over with a reason.

No silent leftover “still open” records.

## REVIEW

Generated report from live data. Department debriefs. Lessons learned. Improvement tasks that can seed next year’s clone.

## Product mapping

| Lifecycle stage | First production | Later |
| --- | --- | --- |
| Plan | Event, type, dates, module flags, plan file attachments | Structured plan editor per discipline |
| Build | Map, locations, zones, staff, vendors, credentials | Logistics slots, artist riders, full volunteer applications |
| Brief | Staff records, basic briefing notes | Signed briefings, training matrix |
| Operate | Live desktop control room | Field mobile, offline maps |
| Respond | Incidents, log, tasks, emergencies, weather alerts | Voice input, public alerts, AI summary |
| Close | Status + outstanding work check | Formal stand-down workflow |
| Review | Generated report v1 | Structured debrief + improvement plan |
